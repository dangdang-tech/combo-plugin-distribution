# 在当前对话安装并提取 Agent

本说明面向执行用户指令的 Codex 或 Claude Code。用户不需要手工打开 Terminal。只使用网页指令中给出的公开仓库完整提交 SHA；不得把 `main`、可移动标签、私有仓库或另一个本地开发版本当成同一发行包。

## 用户复制的请求

下面是供发布网页生成固定版本指令的模板；发布时必须将两处 `PUBLIC_COMMIT_SHA` 替换为同一个实际可匿名获取的 40 位提交。模板占位符不是可安装发行版本。

```text
请在当前客户端安装 Combo 0.2.0 内测插件，并把我们当前对话中已经形成的可复用方法提取成一个可审阅的 Agent。

公开发行仓库：https://github.com/dangdang-tech/combo-plugin-distribution
固定提交：PUBLIC_COMMIT_SHA
请先阅读这个固定版本的安装说明：https://github.com/dangdang-tech/combo-plugin-distribution/blob/PUBLIC_COMMIT_SHA/docs/install.md

只安装到我正在使用的 Codex 或 Claude Code。你可以自动取得并校验这份公开发行包，再调用该客户端的插件安装命令。不要要求我手工打开 Terminal。先检查已有 Combo 插件、同名 MCP 和 Skill。首次安装可以执行；同源同版本须完整校验后才可复用，已有禁用状态须保留。发现旧版、预览版、其他来源或来源无法确认时，停止安装写入，但继续完成公开目标校验和只读核查，给出具体可审阅方案：列出现有项、来源证据及缺口、新目标、拟变更、配置和数据保留方式、恢复限制及验证方法。不要仅问“你希望如何处理”。不得覆盖、启用、禁用或卸载现有项；若需要迁移，请先说明实际能力和仍需补齐的证据，再请我选择保留现状，或授权针对列明项另行准备并审阅迁移。本次安装请求不授权迁移。

安装后，使用你在本次当前对话里已经可用的上下文整理方法，不要读取 Project、其他任务、原始会话文件或凭据，也不要上传或公开分享。如果新安装的 MCP 工具尚未进入当前任务，就由你在当前对话整理方法，按固定版本安装说明调用它的本地编译器；不要另外启动模型或读取旧会话来恢复内容。

请展示真实编译出的完整 AGENT.md、完整 Skill 和 Package digest，说明覆盖范围；仅编译完成时不要声称已经运行。若当前上下文没有足够的方法，请告诉我插件是否已就绪，并请我在已有方法的原对话中继续提取。不要查询其他任务来补齐。
```

## 执行顺序

1. 从当前宿主身份确定 `codex` 或 `claude`，只操作这一端。检查当前任务已经可见的 Combo 工具和 Skill；安装器的命令行清单不能替代当前任务的工具清单。记录名称、当前可见的来源、版本和启用状态；不可见的信息记为未知，不扫描 Project 或旧会话补齐。发现旧 Combo、预览 Combo 或同名工具时，暂停安装写入，继续以下公开包校验与只读核查。不要通过换 marketplace 名称回避冲突，也不要调用旧工具编译来绕过冲突。
2. 检查现成的 Git、Node.js 24 或更新版本，以及当前宿主匹配的客户端 CLI。安装器在 macOS 优先使用宿主提供的 `CODEX_CLI_PATH` 或 ChatGPT/Codex Desktop 自带的 CLI，也支持 `--cli <绝对路径>`。若缺失或配置解析失败，报告具体缺失层；不要自行安装运行时、修复配置或读取认证文件。
3. 在用户当前 Project 之外选一个新的持久化目录，例如用户数据目录中的 `combo-public-test/<完整提交 SHA>`。不存在时才创建；已有目录只能在完整提交、规范公开远端和干净状态均一致时复用，不得覆盖。用 Git 匿名取得 `https://github.com/dangdang-tech/combo-plugin-distribution.git`，检出指令中的完整 SHA。禁用交互认证和 credential helper；获取失败时停止，不要尝试登录私有仓库。此目录将作为本地 marketplace 保留，不是运行后就删除的临时目录。
4. 从该目录执行 `node scripts/verify-release.mjs`，再执行 `node scripts/install.mjs --client <codex或claude> --commit <完整SHA>`，先取得不带 `--apply` 的核查结果。脚本先校验规范远端、完整 SHA、工作区干净状态、允许文件和逐文件 SHA-256，再通过客户端清单检查现有插件、marketplace 来源及 MCP 名称。结合步骤 1 的宿主清单，按下表处理；脚本没有发现冲突不能推翻宿主已经发现的同名工具或 Skill。
5. 只有首次安装分支且宿主清单也无冲突时，直接执行同一命令并加 `--apply`；上述请求已经授权这一步，无需重复确认。已安装分支须从 CLI 定位的真实缓存逐文件复验后才可复用，不能只比较版本号。安装后也须逐文件复验；Codex 的安装结果与本插件 MCP 的完整 transport 必须指向同一缓存，无法定位时停止，不从本地收据猜测。目标为当前用户，避免修改 Project 文件。未知清单格式、校验失败或 CLI 错误均按后文处理，不自行修复配置。
6. 安装或复用成功后，检查当前任务实际能否调用本版本的 `compile_agent_context` 和 `prepare_agent_context`。存在并能确认来源时按本版本 `plugins/<客户端目录>/skills/combo-agent-builder/SKILL.md` 执行。仅 CLI 安装成功不能证明新工具已经进入原任务。
7. 若新 MCP 工具尚不可用，继续使用当前模型已拥有的上下文合成方法，并使用下面的本地编译路径。不要跳到新任务后丢失方法，也不要扫描原会话恢复上下文。宿主支持重载时可提示在原对话重载后继续；Claude 的 `/reload-plugins` 行为依客户端版本和宿主模式而异，不保证重载会连接新的 MCP。不要替用户发送 `--force` 或声称未经测试的原会话热加载已通过。

安装器默认不带 `--apply` 时只返回计划和检查结果。`--apply` 只执行已经核查通过的首次安装；不会把旧版、预览版、禁用状态或未知来源转换成迁移授权。若运行在无执行工具的宿主中，明确报告该限制。

当前任务实际可见的 Project MCP 与同名 Skill 检查必须由宿主模型先完成。安装脚本将客户端管理命令放在新建的空临时目录中，只检查用户级清单，避免 CLI 从发行目录或调用方目录的祖先寻找 Project 配置；Git 和载荷校验仍绑定固定发行目录。脚本不扫描 Project 或配置目录来查找 Skill，不声称覆盖所有宿主来源。它仅清理自己创建且仍为空的临时工作目录。

Claude 的 `mcp get` 在服务器较多时会截断列表。列表不完整或仍有待审批配置时安装器停止写入，列明无法确认的范围，不调用会连接服务器的 `mcp list` 来补查。

## 核查分支与需要用户选择的情况

| 核查分支 | 判定与实际动作 |
| --- | --- |
| `ready_to_install` | 首次安装：没有相关插件、MCP 或 Skill 冲突，公开目标校验通过；可执行用户已授权的安装，复验成功后为 `installed`。 |
| `already_installed` | marketplace 与固定发行目录一致、插件身份与用户作用域明确、版本及实际缓存逐文件校验一致、启用状态有效；复用，不重复安装。 |
| `disabled_preserved` | 当前目标的来源、版本和作用域元数据一致，但被禁用；保留其状态，不启用、不重新安装，也不绕过禁用状态调用本地编译器。CLI 能定位实际缓存时仍逐文件校验；无法定位时明确记为 `not_verified`。禁用项若还有来源冲突，则仍按 `source_conflict` 保留。 |
| `migration_plan_required` | 同一目标注册及发行目录的元数据匹配，但版本不同，需要可审阅迁移计划。此状态不证明旧包可信，默认与 `--apply` 均不执行迁移。其他来源的预览版归入 `source_conflict`，同样提供计划。 |
| `source_conflict` | 来源不明、已知其他来源、独立同名 MCP、多个作用域或其他实际冲突；停止写入，列明证据、缺口及解决这些缺口所需的具体选择。 |

`disabled_preserved`、`migration_plan_required` 和 `source_conflict` 返回 `reviewPlan`，退出码为 `2`；这表示尚需处理的核查结果，不代表插件已就绪。校验或 CLI 异常返回 `failed`，退出码为 `1`。报告时保留实际状态和原因，不把它们改写成安装成功。

名称相似、版本号一致、manifest 自称同一作者或同一个本地缓存目录，都不能单独证明可信来源。本版本没有通过公开固定历史制品与哈希核验建立的旧版迁移允许清单，因此即便看到 `combo-local-preview/combo-context-preview/0.1.1`，也不能仅凭这个标识称其为已验证的官方迁移来源。本版本不支持自动迁移；即使宿主有更新命令，也不能据此放宽来源校验。

发生阻挡时，先把安装器返回的结构化 `reviewPlan` 与当前任务可见的工具、Skill 清单合并成以下可审阅结果，再要求用户做决定。不能补齐的字段须标明“未知”及原因，不得猜测：

- **现有项与目标：**逐项列出插件 ID、marketplace、MCP 或 Skill 名称、可见版本、启用状态、作用域、来源与缓存位置；新目标列出客户端、插件 ID、公开仓库、完整 SHA、版本和已校验的载荷 digest。仅展示必要元数据，不展示环境变量值或凭据。
- **证据与拟变更：**区分已验证事实、名称线索和未知信息；具体指出未来迁移涉及哪些项、可能需要哪些宿主命令、哪些能力未验证。此时命令仅为待审查方案，不执行删除、覆盖、启用或禁用。
- **配置与数据保留：**当前现有配置、缓存和启用状态保持原样；不读取 Project、历史或凭据。若未来动作会替换或删除缓存，明确列出受影响路径以及尚未确定的数据范围，不承诺未知数据会自动保留。
- **恢复与验证：**列出旧制品的可验证来源、哈希、作用域和可重新取得性，以及备份、恢复方式和所需授权。缺任一项就写明无法保证恢复。未来验证须分别检查插件清单、启用状态、缓存逐文件校验、MCP 指向及原任务实际加载；不能用安装退出码代替。
- **一个具体决策：**先完成本请求已授权且能够取得的只读核查，不再询问是否允许核查。明确列名，建议保留现有项、暂缓目标安装。若缺少旧制品的可信公开来源与固定提交，就只请用户补充这项缺失信息及是否确实希望替换；若仅为禁用状态，就明确询问是否希望继续保持禁用，并说明本安装器没有启用能力。不能把补充信息当成迁移授权，也不能把尚无恢复证据的迁移呈现为可执行选项。只有完整方案已经具备执行条件时，才请求对列明变更的最终授权。

原请求明确禁止覆盖、禁用或卸载旧版本时，该限制持续有效；修改安装文档或修复安装器不改变已有授权。只有用户后来针对列明项明确授权、且来源、作用域、保留与恢复方式已经核实，才能另行执行实际支持的迁移动作。本安装器目前没有迁移执行入口。未知来源与多个作用域不得按“官方升级”处理。

## 宿主能力与失败处理

已核查的 Codex Desktop CLI `0.153.4` 提供插件 `add`、`list`、`remove` 和 marketplace 管理；没有插件 `upgrade`、`enable`、`disable` 或 `rollback` 命令。`plugin marketplace upgrade` 更新 Git marketplace 快照，不等于把已安装插件迁移到本地固定发行包。`plugin remove` 会删除插件缓存，不能当作无损备份或回滚步骤。不得编造这些命令，也不得直接编辑用户配置来补齐不存在的迁移能力。

Claude 的更新、启用与禁用能力须按当前宿主 CLI help 和清单核验，不能把 Codex 的结论直接套用；本安装器也不调用这些操作。客户端管理能力、可信旧包身份、数据保留和用户迁移授权是不同条件，必须分别满足。

公开目标校验失败时，不运行客户端安装写入命令；保留现有安装，报告失败的校验层。清单解析失败或作用域不明确时，同样停止写入，报告已查明内容与未覆盖范围。不要把这些情况描述为“用户没有选择”。

若首次安装已经执行了部分宿主命令后失败，报告已成功的命令、失败步骤、已知新增项和当前验证状态；能安全读取清单时做只读复核。marketplace 可能已经注册，插件缓存也可能已经创建；不得声称自动恢复原状或悄悄删除残留。安装器不自动回滚；在恢复方案列明具体对象、影响和限制后，再取得所需的单独授权。重试前重新核验完整目标与现状，不能盲目重跑。

## 本地编译兼容路径

只有在本次固定发行包已经校验、安装来源没有冲突且用户要求提取时使用。模型负责整理当前上下文；CLI 只接受显式标准输入，不调用模型、不扫描历史，也不联网上传。

Codex 使用 `plugins/combo/bin/combo-context.mjs`，Claude Code 使用 `plugins/combo-claude/bin/combo-context.mjs`。给 CLI 的标准输入为下列结构，内容必须来自模型本次整理的实际方法，而不是示例文字：

```json
{
  "protocol": "combo.agent-context-request/1",
  "request": "把当前对话已经形成的方法整理成可复用 Agent",
  "content": {
    "name": "实际的方法名称",
    "description": "帮助谁完成什么",
    "instructions": "完整步骤、输入要求、输出要求和限制",
    "starterPrompts": ["一个实际可用的起始请求"],
    "outputDescription": "输出应包含什么",
    "coverageSummary": "仅整理当前已可用上下文，未检查其他历史"
  }
}
```

Claude CLI 输入在最外层额外包含 `"client": "claude"`；Codex 不需要。MCP 调用由安装适配器确定客户端，不添加这个字段。

由 Agent 用安全的结构化执行工具，将上述 JSON 作为 stdin 交给 `node <固定目录>/plugins/<客户端目录>/bin/combo-context.mjs --output-dir <新的输出目录>`。输出目录放在本次用户认可的产物位置，避免写入当前 Project；不得复用已有目录。不要把方法拼进 Shell 命令，也不要放入原始对话、凭据、私人案例细节或本地路径。

读取本次生成的 `AGENT.md`、`skills/` 内容和 `compilation.json` 中的实际 digest，向用户完整展示。HTML 卡片只有实际打开并可见后才可说已展示。编译失败时保留原方法并说明失败，不得用模拟卡片替代。

用户随后要求使用时，将完全相同的 JSON 交给同一 CLI 的 `--prepare <已经审阅的digest>`。使用返回的完整方法作为当前任务指导，再由当前模型实际完成用户工作。准备成功只证明方法已校验，不证明任务执行成功；这也不会创建独立运行会话或移除原对话上下文。

## 验证边界

`release.json` 记录的分发清单锁定载荷；公开提交 SHA 同时锁定安装脚本及文档。隔离配置中的真实 CLI 安装测试、显式输入的编译测试、当前模型的实际提取、原任务新工具加载和模型后续任务执行是不同证据，分别记录。

Claude 本地 marketplace 与插件加载行为参考 [官方分发说明](https://code.claude.com/docs/en/plugin-marketplaces) 和 [官方安装与重载说明](https://code.claude.com/docs/en/discover-plugins)。已核验本机 CLI help：Codex Desktop CLI `0.153.4`、Claude Code `2.1.234`；这不是两端完整宿主 UAT 通过的声明。
